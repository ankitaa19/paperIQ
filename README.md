# PaperIQ

Local research-paper assistant. It extracts text from PDFs, embeds passages with `all-MiniLM-L6-v2`, searches them with FAISS, and answers questions through Groq using only the retrieved passages.

`llama-3.3-70b-versatile` is not available on this Groq account. The configured chat model is `openai/gpt-oss-20b`. If a Llama chat model appears later, set `GROQ_MODEL` in `.env` to that id.

The five starter papers live in `data/papers/` and are not regenerated by the app.

## Setup

Python 3.12 is used because PyTorch and FAISS publish macOS wheels for it. Python 3.14 is also installed on this machine, but those libraries are not reliable there yet.

```bash
cd ~/Desktop/paperiq
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Put your Groq key in `.env`:

```
GROQ_API_KEY=your_groq_api_key_here
GROQ_MODEL=llama-3.3-70b-versatile
```

`.env` is listed in `.gitignore`. Do not commit it.

## Run

```bash
source .venv/bin/activate
python main.py --check-api
python main.py --extract
python main.py --index
streamlit run app/streamlit_app.py
```

Open the app in VS Code with `code ~/Desktop/paperiq`.

## Layout

- `src/pdf_processor.py` extracts page text with PyMuPDF and caches JSON in `data/processed/`.
- `src/embeddings.py` splits pages into overlapping chunks and embeds them.
- `src/vector_store.py` stores normalized vectors in a FAISS inner-product index, which matches cosine similarity.
- `src/retriever.py` returns paper name, page, score, and text.
- `src/rag_pipeline.py` builds a grounded prompt, or a prompting-only prompt when retrieval is turned off.
- `src/summarizer.py` and `src/paper_comparator.py` call Groq on extracted text. A summary is saved only after a successful response, and it is reused only when the extracted text, prompt, and model still match. The summary page shows that result after Generate summary is clicked.
- Uploaded PDFs are stored in `data/papers/` next to the five sample papers, extracted with the same pipeline, and added to the search index. Sample papers cannot be removed from the Upload page. Removing an uploaded paper deletes its PDF, extracted text, and summary, then rebuilds the index.
- `src/evaluation.py` runs three live questions: one clearly in the corpus, one about RAG, and one with no support in these papers.
- `app/streamlit_app.py` is the dashboard.

## What the evaluation does

`Evaluation and Experiments` measures retrieval time, whether the expected file appears in the top results, answer time, and whether the RAG answer reports missing evidence. It does not ship with filled-in accuracy percentages.

## Prompting, RAG, and fine-tuning

Prompting-only asks the configured Groq model to answer from its pre-trained knowledge. No paper text is added. RAG embeds the question, retrieves passages from the local FAISS index, and sends those passages with the question. Fine-tuning would change the model's learned behavior with extra training. It is not used here.

RAG fits this project because the document set can change when someone uploads a PDF. A fine-tuned model would not automatically know that new paper, and fine-tuning by itself does not stop unsupported claims. Prompting and RAG are enough for this mini-project. Fine-tuning could be considered later if evaluation showed a need for a specialized answer format or domain-specific behavior that retrieval does not provide.

## Limits

- Summaries and comparisons use the opening pages and the closing pages, so a detail that appears only in the middle can be missed.
- The embedding model is small and can retrieve a related but wrong passage.
- Groq can still phrase an answer more strongly than the excerpt supports. The RAG prompt tells it to refuse when evidence is missing; the evaluation view shows that refusal flag next to the sources.
- Index files and processed JSON are local caches. Delete `vector_db/` or `data/processed/` if you want a clean rebuild. Do not delete `data/papers/`.
